Site Rules

A site rules file tells Tubarr how to handle specific video sites: which metadata to scrape from a video page, how to find new videos on a channel page, and how to make requests the site will accept. It can be YAML, TOML, or JSON. See example-scrape-rules.toml for a full example.

A site only needs the parts it changes. Anything left out keeps Tubarr's built-in rules for that site (if any), and yt-dlp is used for anything with no rules. For example, this turns FlareSolverr on for Rumble and keeps the rest: 

[[sites]]
domain = "rumble.com"
flaresolverr = true

Site settings

domainrequired
The base domain of the video site the rules apply to (e.g. example.com).
impersonateoptional
Makes requests look like a real browser: chrome, firefox, safari, or brave. Leave it out to keep a built-in site's setting, or set it to none (or "") to turn impersonation off.
user_agentoptional
The user agent sent to the site, by Tubarr and by yt-dlp (your own custom yt-dlp --user-agent takes priority). It should match the impersonate browser, as some sites block a mismatch. Leave it out to use one matching impersonate. FlareSolverr sites always use FlareSolverr's user agent.
flaresolverroptional
Set it to true to get past Cloudflare challenges using the FlareSolverr instance set on the settings page. Tubarr asks FlareSolverr to solve the challenge once, then uses its cookies and user agent while impersonating Chrome, for its own requests and for yt-dlp (which needs curl_cffi installed for --impersonate). If Cloudflare challenges again, Tubarr asks FlareSolverr for a fresh solve and retries once. It takes priority over impersonate. If FlareSolverr isn't set up or can't be reached, Tubarr logs a warning and falls back to impersonate (or normal requests) for the rest of that crawl.
flaresolverr_timeoutoptional
How many seconds FlareSolverr may take to solve the site's challenge (default 60, allowed 10 to 300). Some sites need 120 or 180.

Metadata selectors: [[sites.selectors]]

Each selector scrapes one metadata field from a video page. A field can have several selectors; they are tried in order, and the first to give a value is used.

fieldrequired
The key added to the video's metadata JSON (e.g. title, description). Recognized fields:
  • Strings: title, description, thumbnail, direct_video_url
  • Full dates: upload_date, release_date, date
  • Years: year, release_year
  • Durations: duration (e.g. 3723) and duration_string (e.g. 1:02:03). duration is written to the metadata JSON in seconds, taken from duration, or from duration_string if there's none. Either can be 1:02:03, seconds, or an ISO 8601 duration like PT1H2M3S or P1DT2H.
  • Any other field is written to the metadata JSON as is.
selectorrequired
A CSS selector for the element holding the value. For example, the contents of a <p> tag with class title can be selected with p.title.
attroptional
The attribute to read. Leave it out to read the element's text content.
json_pathoptional
If the value is JSON (e.g. a <script type="application/ld+json"> tag), the path to the wanted value, in gjson syntax. If the JSON is an array (JSON-LD often is, e.g. [{"embedUrl": ...}]), start the path with #. (e.g. #.embedUrl).
regexoptional
A regular expression applied to the value (after json_path). The first capture group is kept if there is one, otherwise the whole match. Elements that don't match are skipped.

Follow-up requests: [[sites.selectors.fetch]]

Some sites don't put a value (often the video's direct_video_url) in the page. Their player requests it separately, e.g. from a JSON API, using an ID that is in the page. Fetch steps let a selector follow the same requests.

A selector can have any number of fetch steps, run in order. Each one requests a URL built from the value so far, and reads the next value from the response:

urlrequired
The URL to request. {value} is replaced with the value so far, as is (use regex to trim it first). Relative URLs are resolved against the previous URL, so url = "{value}" follows a scraped link.
selectoroptional
For an HTML response, the element holding the value.
attroptional
The attribute of that element to read. Leave it out to read its text content.
json_pathoptional
For a JSON response (or value), the path to the value.
regexoptional
As above.

Requests use the site's impersonate, user_agent, flaresolverr, and cookie settings, and send the previous URL as the Referer.

To find the requests a site makes, open a video page with your browser's developer tools on the Network tab, start the video, and look for the request returning the .m3u8 or .mp4 (or a JSON response containing it). Then look for a part of that request's URL (often an ID) in the video page's source.

Warning: every element matching selector (and regex) is tried in turn until one gives a value, and each one makes the fetch requests. Keep selector and regex specific, so a broad selector like script doesn't send a request for every match.

For example, if a video page holds its embed link in JSON-LD and the stream URL comes from a JSON API:

[[sites.selectors]]
field = "direct_video_url"
selector = 'script[type="application/ld+json"]'
json_path = "#.embedUrl"
regex = 'embed/([a-z0-9]+)'

  [[sites.selectors.fetch]]
  url = "https://example.com/api/video?id={value}"
  json_path = "streams.hls.url"

Or, if the page embeds a player page with a <source> tag:

[[sites.selectors]]
field = "direct_video_url"
selector = "iframe[src*='/player/']"
attr = "src"

  [[sites.selectors.fetch]]
  url = "{value}"
  selector = "video source[src]"
  attr = "src"

Fetch steps can't handle sites whose requests need tokens generated by the page's JavaScript.

Channel crawl rule: [sites.crawl]

Optional. Tells Tubarr how to find new videos on a channel page, instead of using the built-in scraper or yt-dlp. It uses the site's impersonate setting.

selectorrequired
The elements holding the video links (e.g. a[href]).
attroptional
The attribute holding the link. Leave it out to read the element's text content.
json_pathoptional
If the value is JSON (e.g. a <script> tag), the path to the video URLs, in gjson syntax. With item_path, it's the path to the URL within each video's object (e.g. url).
item_pathoptional
For JSON: the path to the list of video objects (e.g. items.#(object_type=="video")#). Use it with preview_fields, so each video's URL and details are read from the same object.
includeoptional
A regular expression video URLs must match.
excludeoptional
A regular expression video URLs must not match.
strip_queryoptional
Removes ?... from video URLs so the same video isn't added twice.
itemoptional
For HTML: the element holding each video's card on the channel page (e.g. .episode). preview_fields are read inside the card containing each link. Leave it out to read them inside the link element itself.
preview_fieldsoptional

Only used to preview videos on the Available page before they're downloaded. Details saved with a downloaded video always come from selectors, read from the video's own page.

Read from the channel page Tubarr already loads, so they cost no extra requests. Each entry has a field (title, thumbnail, upload_date, duration, or duration_string), plus selector, attr, json_path, and regex as for metadata selectors. fetch isn't allowed. If a field is listed more than once, the first one found is used.

duration and duration_string give the length shown on each video's thumbnail. duration is used if found, otherwise duration_string. Either can be 1:02:03, seconds, or an ISO 8601 duration like PT1H2M3S. 

[sites.crawl]
selector = "a[href]"
attr = "href"
include = "/episodes/"
item = ".episode"
preview_fields = [
  { field = "title", selector = "h5" },
  { field = "thumbnail", selector = "img", attr = "data-src" },
  { field = "duration_string", selector = ".duration" },
  { field = "upload_date", selector = "time" },
]
