Writing an operation

An operation is one line made of parts divided by :. Metadata ops start with the field they change; filename ops have no field, since they change the filename. 

title:prefix:[Archive]       a metadata op: field, operation, value
prefix:[Archive]             a filename op: operation, value
  • The last part is the rest of the line. title:set:Cats: The Movie sets the title to Cats: The Movie, with no escaping.
  • A : in a middle part, such as the text replace looks for, is written \:, and a \ is written \\: title:replace:Part 1\: : removes Part 1: .
  • Spaces count. title:prefix:[Archive] ends in a space, so the title becomes [Archive] My Video. Spaces at the end of a line are kept, in the boxes and in ops files.
  • Operation names aren't case-sensitive (title:SET:x works). Field names and values are, since metadata field names are.
  • Entered one op per line. In an ops file, a line starting with # is a comment.
  • Values can use the video's metadata with {{field}}, e.g. title:prefix:{{uploader}} - . A prefix, suffix or replacement whose tags can't be filled for a video is skipped for it. See Template tags.

Ops set on a channel apply to all its channel URLs. A channel URL's own ops (in its custom settings) are added to the channel's, unless Replace the channel's is ticked under them.

Metadata ops

Metadata ops change the video's metadata file (JSON or NFO), and through it the tags embedded in the video.

Some rules:

  • One op can change several fields, listed with commas: actor,director:set:Spielberg sets both. Don't list a field another one already covers (see Group fields): title already changes fulltitle, so title,fulltitle:prefix:[Cats] would add the prefix to fulltitle twice.
  • Dates must be written YYYY-MM-DD when set (release_date:set:2024-05-01), a year as YYYY.
  • NFO metadata files don't fill {{field}} tags, and filtered metadata ops only work on JSON files when Metarr is run on its own. (In Tubarr, filters are checked by Tubarr, so they work for every video.)

Group fields

A group field changes several fields at once, so the same op reaches every place a player might read. Some single fields cover their other forms too: title is the title players show, so it also changes fulltitle, which the embedded title is taken from.

The order metadata ops run in

Ops run in a fixed order by type, not in the order they're written, since a video's ops are gathered from its channel, channel URL, ops files and matched filtered ops:

  1. delete-date-tag, so old tags are gone before anything else moves them
  2. set on a group, then other set ops
  3. copy-to, then paste-from
  4. replace, replace-prefix, replace-suffix, keep-after / keep-before, regex-replace
  5. prefix, then suffix
  6. date-tag, outermost

So title:set:{{fulltitle}} with title:prefix:[Cats] and title:date-tag:prefix:ymd gives [24-05-01] [Cats] Full Title.

Filename ops

Filename ops rename the finished video (and its metadata file), without the extension. They have no field.

OperationExampleWhat it does
setset:{{uploader}} - {{fulltitle}}Sets the whole name. One per video.
prefix / suffixprefix:[Cats] Add text to the start or end, as for metadata ops.
replacereplace:_: Replaces every match (case-sensitive).
replace-prefix / replace-suffixreplace-suffix: _v1:_finalReplace text only at the start or end.
regex-replaceregex-replace:[[^(.*) - (\d{4})$]]:$2 $1Replaces every regex match.
keep-after / keep-beforekeep-before: |Keep only the text after or before the first delimiter.
date-tagdate-tag:prefix:YmdAdds the video's date. One per video.
delete-date-tagdelete-date-tagRemoves every date tag from the name.

yt-dlp names downloads title [id], so two videos with the same title can't clash, and finished videos keep that name unless a filename op sets another. To name them by their full title, add set:{{fulltitle}} ({{title}} is often cut short).

Filename ops run in this order:

  1. delete-date-tag
  2. set
  3. replace, replace-prefix, replace-suffix, keep-after / keep-before, regex-replace
  4. The rename style (below)
  5. prefix, then suffix, so they keep their spaces as written
  6. date-tag

The rename style is spaces (underscores become spaces), underscores (spaces become underscores), fixes-only (only fixes broken contractions, like Don t to Dont), or skip.

Date tags

A date tag is the video's date in brackets, made from its release or upload date. It goes at the prefix or suffix; adding one replaces a date tag already in that place, so running the ops again doesn't stack them. delete-date-tag removes date tags from anywhere in the field, in any of the formats below.

FormatTag for 1 May 2024FormatTag for 1 May 2024
Ymd[2024-05-01]ymd[24-05-01]
Ydm[2024-01-05]ydm[24-01-05]
dmY[01-05-2024]dmy[01-05-24]
mdY[05-01-2024]mdy[05-01-24]
md[05-01]dm[01-05]

A capital Y is a four-digit year, a lowercase y two digits, and md and dm leave the year out. Because of those two, brackets holding two numbers like [10-12] at the start or end of a field are read as a date tag, and replaced or deleted by date tag ops.

Download filters

Filters decide which of a channel's videos are downloaded. Each line is field:type:value:must or field:type:value:any.

TypeExamplePasses when
containstitle:contains:live:mustThe field holds the value
regex-containstitle:regex-contains:[[(?i)^ep\.? ?\d+]]:mustThe field matches a regular expression (RE2 syntax), written between [[ ]] exactly as the regex engine reads it. Unlike the other types it keeps case, so start the pattern with (?i) to ignore it.
omitstitle:omits:trailer:mustThe field doesn't hold the value
equalsuploader:equals:kino casino:mustThe field is exactly the value
not-equalslanguage:not-equals:de:mustThe field is anything else
not-equals with no valuetitle:not-equals::mustThe field has something in it, so it isn't missing, null or blank
more-thanduration:more-than:600:mustThe field is a number above the value
less-thanduration:less-than:3600:mustThe field is a number below the value
  • Matching isn't case-sensitive, except for regex-contains.
  • must: every must filter has to pass. any: at least one any filter has to pass.
  • Leave the value out to check whether the field is there at all: chapters:contains:must needs a chapters field, is_live:omits:must needs it to be missing.
  • List several fields with commas to check them all: title,fulltitle:contains:lion:must passes when either field holds lion. omits and not-equals need every field to pass, so title,description:omits:sponsor:must skips videos with sponsor in either.
  • A more-than or less-than filter on a field the video doesn't have is skipped.
  • From Date and To Date (YYYYMMDD) only download videos uploaded in between.
  • Videos you choose yourself (from Available, Download As or by URL) skip download filters.
title:contains:podcast:any
title:contains:interview:any
title:omits:short:must

Downloads videos with podcast or interview in the title, but never ones with short.

Filtered ops

A filtered op only runs when the video's metadata matches all of its filters. Each line is one or more filters and one or more ops, divided by ||. Filters are written as above, without must/any. Several filters, or several ops, are joined with &&: every filter must match, and then every op runs. 

title:contains:cat||genre:set:Cats                                filtered metadata op
title:contains:cat||prefix:[Cats]                                 filtered filename op (the filter reads metadata, the op renames)
title:contains:cat&&duration:more-than:3600||prefix:[Long Cats]   only for cat videos over an hour long
title:contains:cat||title:suffix: [Cats]&&genre:set:Cats          two metadata ops for the same filter
title:contains:lion||set:{{fulltitle}}&&prefix:[Animals] &&suffix: - Animal Kingdom   three filename ops
  • Put the && straight after an op's value, as a space before it becomes part of the value: title:suffix: [Cats] &&genre:set:Cats adds [Cats] , ending in a space. A space after the && is fine.
  • A && inside an op's value is written \&&, so it isn't read as joining two ops: title:contains:tom||title:set:Tom \&& Jerry sets the title to Tom && Jerry. A regex can't hold a && at all, so write &{2} instead.
  • The ops still run in their usual order (see metadata ops and filename ops), not the order they're written in.
  • Filters check the metadata as it was downloaded, before any metadata op changes it, so title:contains:[cats] won't see a title:prefix:[Cats] from the same run. Edit & Re-Process checks the metadata as the last run left it instead.
  • To run an op when either of two filters matches, write the line once for each filter.
  • A matching filtered op beats a plain op that sets the same thing, e.g. a filtered set filename op beats the plain one. Of two matching filtered ops that set the same thing, the one from the nearer level (see Profiles) wins, then the earlier line.
  • To limit an op to one channel's videos, filter on its channel URL: channel_url:contains:youtube.com/@ChannelA||title:prefix:[A] . (In Tubarr, a channel URL's custom settings do this more simply.)
  • A | at the end of the filter's value is written \| to distinguish it from the filter/operation || separator. For example, title:contains:|CATS\|||description:suffix: - Cat videos. would look for |cats| in the title field and, if found, suffix the description field with - Cat videos.
  • Likewise, a && in a filter's value is written \&&, and a & at the end of it \&, so they aren't read as joining two filters. For example, title:contains:Tom \&& Jerry||genre:set:Cartoons looks for tom && jerry in the title field.

Move ops and output directories

A move op sends finished videos whose metadata matches its filters to another directory: title:contains:podcast||/media/podcasts. As with filtered ops, join several filters with && to require all of them: title:contains:podcast&&duration:more-than:3600||/media/long podcasts. The first move op that matches wins, and a channel URL's own move ops are checked before the channel's. Like filtered ops, they check the metadata as downloaded, and Edit & Re-Process doesn't use them (see below).

In a move op, {{channel_url_output_directory}} is the channel URL's Metarr Output Directory, or its video directory if it has none, e.g. title:contains:podcast||{{channel_url_output_directory}}/Podcasts puts podcasts in a folder inside it, so changing the output directory changes where podcasts go too. {{channel_output_directory}} does the same with the channel's directories.

Where a finished video goes, first match first:

  1. The Download As Post-Process Directory chosen for that video
  2. The first matching move op
  3. The channel URL's (or channel's) Metarr Output Directory
  4. Otherwise it stays in the video directory

Edit & Re-Process only uses the first: without a Post-Process Directory, the files stay where they are, so a video never changes folder because of its own ops.

Tubarr never creates download folders: a video or JSON directory must already exist, so an unmounted drive isn't filled by mistake. A directory using template tags needs its fixed part to exist. Metarr creates its own output folders, so when downloading, an Output Directory or move op folder inside a video or Output Directory only needs that directory to exist.

Transcoding

Video Transcode Codecs and Audio Transcode Codecs say which codecs Metarr converts the finished video to, one line each. Anything not mentioned is copied as it is.

LineMeans
hevcConvert every video codec to HEVC (HEVC itself is copied).
h264:hevcConvert only H.264 to HEVC.
hevc:hevcEncode HEVC video again as HEVC, every time it's processed.
hevc:copyNever encode HEVC video, whatever its Video Encoder Args say.
dts:ac3Convert only DTS audio to AC-3.

A plain codec applies to everything a source:target line doesn't name, whatever order the lines are in: 

hevc
vp9:av1

converts everything to HEVC, except VP9, which becomes AV1. Only one plain codec is allowed, and each source codec can only be named once.

lc_, mc_ or hc_ in front of a source codec makes a line apply only to videos with low, medium or high compression, worked out from the bitrate. Converting a highly compressed video saves little space and loses quality, so this can skip the ones not worth it: 

lc_h264:av1
mc_h264:hevc

converts low-compression H.264 to AV1 and medium-compression H.264 to HEVC, and copies high-compression H.264 as it is. A line with a level comes before one for the same codec without, which comes before the plain codec. A prefix needs a target codec, and if a video's level can't be worked out, only lines without a prefix apply to it.

The borders depend on the codec, as newer codecs need fewer bits for the same picture or sound. Anything above the mc_ border is lc_. For a 1080p video at 30 frames a second:

Video codechc_ belowmc_ below
H.264, VP82.5 Mbps5 Mbps
HEVC, VP91.5 Mbps3 Mbps
AV11.25 Mbps2.5 Mbps
MPEG-25 Mbps10 Mbps

The video borders grow with the picture size and frame rate: a 1080p video at 60 frames a second gets twice these, and a 4K one at 30 frames a second four times. For stereo audio:

Audio codechc_ belowmc_ below
MP3, AC-3128 kbps256 kbps
AAC, E-AC-3, Vorbis96 kbps192 kbps
Opus77 kbps154 kbps
MP2, DTS192 kbps384 kbps

A 5.1 track gets three times these. Lossless audio (ALAC, FLAC, PCM, TrueHD, WAV) nearly always counts as lc_. MKV and WebM files don't store their audio's bitrate, so when any line has a prefix, Metarr works it out by reading the whole file. That's quick for most videos, but can take a few minutes for very long ones on a slow drive or network share.

  • Video codecs: av1, h264, hevc, mpeg2, vp8, vp9. Audio codecs: aac, ac3, alac, dts, eac3, flac, mp2, mp3, opus, pcm, truehd, vorbis, wav. Common other names work too (h265, x264, libmp3lame).
  • GPU Acceleration encodes on the graphics card (auto, cuda, qsv or vaapi, with GPU Node Path for VA-API, e.g. /dev/dri/renderD128).
  • Video Encoder Args are FFmpeg options used only when Metarr encodes to a codec, one codec:args line per target codec, e.g. av1:-crf 35 -preset 6. A codec without a line uses its encoder's defaults. Metarr adjusts three of them to suit GPU encoders too: -crf sets the quality (lower is better and larger, up to 51 for H.264 and HEVC and 63 for AV1, VP8 and VP9, with VP8 starting at 4), -pix_fmt sets the pixel format (e.g. yuv420p10le for 10-bit, or yuv420p to keep 8-bit for older devices), and -vf sets filters, e.g. hevc:-vf scale=1280:-2 to scale the video to 1280 pixels wide. If the encoder can't take the pixel format, Metarr uses the same format in the form it does take, or stops with an error naming the formats it can.
  • Audio Encoder Args work the same way for audio codecs, e.g. aac:-b:a 160k -ac 2 for 160 kbps stereo AAC. An -af filter runs before the channel layout filter Metarr gives Opus, and an -ar sample rate replaces the 48 kHz Metarr gives AC-3, E-AC-3 and DTS.
  • A video already in a codec is kept as it is, so that codec's args don't run on it, with two exceptions. A line such as hevc:hevc encodes it again every time it's processed. A -pix_fmt it isn't in encodes it once, e.g. hevc:-pix_fmt yuv420p10le with an 8-bit HEVC video, unless hevc:copy or a plain copy is set. Other args, such as -crf, can't be checked on a finished video, so they never start an encode, and a -vf left out this way logs a warning. Audio works the same way, with -ac and -ar in place of -pix_fmt and -af in place of -vf: aac:aac encodes AAC again every time, and aac:-ac 2 encodes 5.1 AAC once. Opus always reads back as 48 kHz, so its -ar never starts an encode.
  • -pass in Video Encoder Args is the number of encoding passes, e.g. h264:-b:v 3M -pass 2. Extra passes help most when aiming for a set bitrate, and take that many times as long. H.264, HEVC and MPEG-2 take up to 3 passes, AV1, VP8 and VP9 up to 2, and more are lowered to that. H.264, HEVC, AV1 and MPEG-2 need a target bitrate (-b:v) instead of -crf for more than one pass, while VP8 and VP9 can use either. GPU encoders always make one pass. The Post-Processing page shows which pass a video is on.
  • -b:v in Video Encoder Args is the target bitrate, written with k, M or G: one for every video, e.g. av1:-b:v 3M, or one per resolution, e.g. av1:-b:v 720=1.5M,1080=3M,2160=10M. A video gets the bitrate for the largest resolution at or below its own, going by the shorter side, or the smallest one listed if it's smaller than all of them. The resolution is the downloaded video's, before any -vf scaling. A target above the downloaded video's own bitrate is lowered to it, as encoding at more than the source has makes a bigger file, not a better one. The lowest target is 1k, and 0 means none.
  • H.264, HEVC and AV1 aim for a quality or a bitrate, not both, so give them -crf or -b:v, and Tubarr refuses a line with both: H.264 and HEVC would ignore the bitrate, and AV1 wouldn't start. VP8 and VP9 can use both, aiming for the quality without going over the bitrate.
  • Extra FFmpeg Args are added every time FFmpeg runs, even when the video is only copied to update its metadata, e.g. -movflags +faststart. Some options aren't allowed there:
    • -crf, -pix_fmt, -vf, -pass and -b:v only work when encoding, so they go in Video Encoder Args.
    • -af, -ac, -ar, -b:a and -q:a only work when encoding audio, so they go in Audio Encoder Args.
    • Codec options (-c, -c:v, -c:a and the like) would replace the codecs set in Video Transcode Codecs and Audio Transcode Codecs, skipping the check that the output container can hold them. Choose codecs there instead.
    • -vn would leave a file with no video.
    • -f would write a different format from what the file's extension says.
    • -filter_complex and -lavfi can leave FFmpeg running forever.
    • -shortest stops at the shortest stream, and a thumbnail is a single frame, so it can leave a file with no video or audio.
  • Keep Original Video Files keeps the downloaded video whenever Metarr writes a new one from it, even just to add metadata. It stays where it was downloaded, under its own name, unless the new video ends up with exactly the same path; then it's renamed name_mbackup.ext. Tubarr doesn't keep track of it, so deleting the video's files leaves it.
  • Post-Process After Download set to No leaves each video unprocessed once it downloads, Download As videos included. Post-process them later from the channel's videos page, with Post-Process pending, Post-Process Selected or Edit & Post-Process Selected. Download As options are kept and used then.

yt-dlp download options

  • Preferred Video Codecs and Preferred Audio Codecs, one per line, most wanted first. yt-dlp takes the best stream in the first codec it finds, then the next, and falls back to the best stream of any codec. E.g. av1 then vp9 gets AV1 where there is one, else VP9, else the best there is.
  • YT-DLP Output Ext is the container yt-dlp merges into (mp4, mkv, webm and so on). Metarr's Output Extension is separate: what the finished video is remuxed to.
  • Max Filesize skips larger videos: 500m, 2g.
  • Max Resolution downloads the largest size up to this, e.g. 1080, 720p or 4k, or the smallest above it when a video has nothing that small. It goes by the shorter side, so a vertical 1080×1920 video counts as 1080p. It picks within the Preferred Video Codecs, so a preferred codec only offered above the limit still wins.
  • Extra YT-DLP Video Args are added to the download command, Meta Args to the metadata fetch and Crawl Args to channel crawls. A channel URL's own extra args replace the channel's rather than adding to them, and Download As's replace the channel URL's.
  • External Downloader hands the transfer to aria2c, axel, curl and the like, with its own Args.

Which setting wins

  1. Channel settings apply to all its URLs. Settings the channel leaves blank come from its profile, if it has one.
  2. A channel URL's custom settings replace the channel's where set, and leave the rest to the channel. Its filters and ops are added to the channel's instead; where a URL op and a channel op both set the same thing (e.g. both title:set), the URL's wins. Its move ops are checked first. A URL's own profile fills in what the URL leaves blank, before the channel's settings do.
  3. Download As options are for one video. Blank ones use the channel URL's; its op, transcode codec, encoder args and extra FFmpeg args boxes replace the channel URL's, so an empty one means none.

An ops file's ops replace the matching ops typed into the same settings. Every level's file is used, as part of its level: a nearer level's ops, typed or in a file, still beat a farther level's file.

Replace the channel's, under a URL's filters, move ops or one of its op lists, uses only the URL's own list and file for it, with its profile's, leaving out the channel's. A channel's Replace the profile's does the same with its profile's. Ticked with the list empty, there are none of that kind.

Profiles

A profile is a named set of settings, made on Settings → Profiles. Choose one for a channel, or for one of its URLs, and it fills in whatever is left blank there. Each setting comes from the first of these that sets it:

  1. The channel URL's custom settings
  2. The channel URL's profile
  3. The channel's settings
  4. The channel's profile

Filters and ops are added together the same way, the nearer one winning where two set the same thing, unless a list's Replace box is ticked. A profile's video directory can use template tags, e.g. /media/{{channel_name}}, so one profile can serve many channels. A channel with no video directory of its own needs a profile with one, and a profile can't be deleted while a channel or URL uses it. Profiles can't pause channels.

Download As

Download As… downloads one video with its own filename, directories, thumbnail, ops, yt-dlp options and post-processing options, starting from its channel URL's. They're kept with the video, which Available marks Customized: downloading it again from there, e.g. after it fails or is canceled, uses them too, and Edit & Post-Process and Edit & Re-Process open with them later. Those two only run Metarr on files already downloaded, so they have no download options. A Login entered in Download As is used for that one download and never saved. Revert to Defaults goes back to the channel URL's. Options left the same as the channel URL's aren't kept, so the video then isn't customized and follows later changes to the channel URL. Each time the dialog opens, the channel URL's ops, including its ops files, are filled in fresh, keeping any lines you added or deleted for that video. To give several videos from one channel URL the same options, select them on Available and choose Download As… above the list, or for downloaded videos, select them on the channel's downloaded videos and choose Edit & Post-Process Selected or Edit & Re-Process Selected. A filename or custom thumbnail is for one video only.

Downloads and concurrency

Queued videos start first in, first out, through these limits in turn:

  1. The channel's Max Concurrency (one at a time when 0), or a channel URL's own if it has one. A channel's videos wait their turn here.
  2. Domain Limits (Settings), per site.
  3. Download Concurrency (Settings), across all channels.

A video keeps its place under all three while its metadata is fetched and checked against the filters, and while it downloads. So within one channel videos start in the order queued; across channels, the next slot goes to whichever channel's video has waited longest for it. Crawl Concurrency limits how many channels are checked for new videos at once, and Post-processing Concurrency how many Metarr runs happen at once (a channel can set a lower limit of its own). 0 means unlimited.

A download that fails is run again up to Download Retries times (2 when blank), after a short random wait. If the site flags Tubarr as a bot, it stops at once. yt-dlp also retries dropped connections itself within each run. On channel URLs that download new videos automatically, a video that still fails is tried again by up to 3 later crawls, then waits on the Available page for you to retry. Crawls don't retry videos you downloaded yourself. A crawl while the URL doesn't download automatically leaves its failed videos to you as well, so turning automatic downloads back on only downloads new videos.

Notifications

Notification URLs are called when a channel gets new videos, e.g. a Plex library refresh (http://plex:32400/library/sections/1/refresh?X-Plex-Token=…) or a webhook. On a channel's Notifications tab, choose the channel URLs (or all of them) and add the URLs.

Logins and cookies

  • A channel URL can have a username, password and login URL for sites that need an account. Passwords are stored encrypted.
  • Cookies From Browser uses a browser's cookies (e.g. firefox) for yt-dlp, along with any login or global cookies. Where both have the same cookie, the login or global one is used.
  • Use Global Cookies reads the site's cookies from every browser Tubarr can find, for custom crawl rules and yt-dlp.

Blocked domains and site rules

When a site flags Tubarr as a bot, Tubarr stops using its domain for a while. Blocked Domains lists them and can unblock one early. Site Rules tell Tubarr how to handle a particular site: metadata to scrape, how to find a channel's videos, and how to get past Cloudflare (site rules documentation).
